# 拾图开发与设计

## 代码结构

| 位置 | 内容 |
| --- | --- |
| `app/src/main/` | 两版共用。Compose 界面，`core` 负责 OCR、向量和排序，`data` 管理 MediaStore、解码与 SQLite，`work` 负责信息准备。 |
| `app/src/lite/`、`app/src/standard/` | 应用名称和版本资源。Chinese-CLIP 的模型资产与许可资源只进入普通版。 |
| `app/src/test/`、`app/src/androidTest*/` | JVM 测试和 Android 行为测试。描述模型的设备测试只随普通版测试构建。 |
| `scripts/fetch_models.py`、`*.lock.json` | 在构建机下载、校验和派生 ONNX 资产。手机安装后直接离线使用。 |

## 图库与索引

图库通过 MediaStore 批量读取已授权的图片记录。目录、时间和格式可用于筛选，排除目录同时影响索引和结果范围。缩略图按需加载。模型只在处理当前图片时解码像素，索引和原图分开保存。

「补全搜索信息」先固定本轮图片 ID，默认 100 张。所选阶段依次运行 OCR、文字向量、相近特征，普通版最后计算画面描述特征。SQLite 按图片指纹与特征版本判断可复用性。每张写入时核对当前图片是否还可访问、指纹是否仍匹配。暂停等当前原生调用返回，继续时跳过成功项。失去权限、高温或未充电且电量不高于 15% 时停止继续处理。模型会话按阶段协调和释放，减少同时驻留的内存。

两版共用 Kotlin、Compose、SQLite/FTS4、WorkManager 和 ONNX Runtime Android。普通版沿用 `dev.localphotos.shitu`，在同签名覆盖升级时复用旧记录。轻量版用 `dev.localphotos.shitu.lite`，首次安装单独建立索引。0.0.1 整理发布时重置显示版本，Android 安装版本号延续递增。

## 四个模型各做什么

| 模型 | 输入和输出 | 用途 |
| --- | --- | --- |
| PP-OCRv6 tiny | 检测图中候选文字框，逐框识别为文本 | 新识别默认使用。旧 OCR 原文和已有索引仍可查。 |
| BGE-small-zh-v1.5 INT8 | OCR 文本段落或搜索词转为 512 维向量 | 给文字搜索补充近义结果，明确原词和文件名命中优先。 |
| MobileNetV4 Conv Small | 整图等比留边，提取 1280 维视觉特征 | 以图找图，结合低成本图像特征与必要的时间线索。 |
| Chinese-CLIP RN50 INT8 | 图像和中文描述分别编码为同一空间中的 1024 维向量 | 普通版的描述找图，按向量相似度排列画面候选。 |

OCR 普通图有界采样后整图识别，横竖长图按同一规则重叠分段，保留更多小字像素。输出坐标还原到整图，去重和整理行序。索引另存断词、归一化与检索变体，便于查漏，也能回看 OCR 原文。动态图片使用系统静态解码的一帧。0.0.2 复用模型输入缓冲区，同宽文字行最多四行一批推理，恢复原输出顺序。较宽的行自动缩小批量。

文字检索结合 SQLite FTS、原词、文件名和字符归一化，再用段落向量补候选。相近图片检索独立保存视觉特征，时间只参与部分候选的排序，不限制跨日期查找。普通版的画面描述独立检索，不把 OCR 文字分数合进画面结果。不同模型的向量不可直接互比。更换模型、输入处理或输出格式时，只为受影响的特征确定重建范围。

## 开发经过与取舍

- 最初从手机多目录截图的 OCR 找回做起。真机反馈集中在长图小字、段间断词和错误候选，由此加入横竖长图分段、坐标整理和原词优先。后续以 PP-OCRv6 tiny 接替 ML Kit，保留旧识别记录。
- 以图找图从重复版本扩展到画面构图近似。真实图库的分组标记帮助发现漏召回和候选过多的问题。由于同一场景可能隔很久才保存，时间适合作为辅助。标注不全的图片对保留为未知。
- 描述找图从电脑实验接入 Chinese-CLIP，再与文字、相近特征整合为一次分阶段准备。曾试用更大的图文模型及候选重排，移动测试模型包超过 2 GiB，还需要额外运行时和索引。0.0.1 移除这些实验入口、模型和运行时，保留现有排序规则、技术详情与性能报告。把画面描述做成普通版的可选体量，轻量版仍能查文字和找相近图片。
- 0.0.3 将搜索方式合入搜索框，补全入口常驻设置。单图分享使用 Android 系统分享面板和临时只读 URI 授权。旧测试标记留在 SQLite，图库多选继续用于准备和管理识别记录。
- 0.1.0 把索引覆盖、范围和运行控制放进补全页。性能报告分开呈现批量准备与单次查询，技术详情按概览、OCR、特征和匹配组织。
- 0.1.1 普通版试用 RN50。B/16 画面向量随模型版本失效，补全时按需替换。文字和相近图片索引继续复用。

## 验证与诊断

```sh
./gradlew :app:testLiteDebugUnitTest :app:testStandardDebugUnitTest
./gradlew :app:connectedLiteDebugAndroidTest :app:connectedStandardDebugAndroidTest
```

设备测试需要 ARM64 和已准备的对应模型资产。发布前核查两个 APK 的签名、ABI、对齐、应用 ID、联网权限和模型清单。普通版还需检查覆盖安装及旧索引读取。仓库测试样本来自公开素材或程序生成。私人图片、标签、向量及实验回放留在本地。

单图技术详情可核对 OCR 解码、检测、找框、识别及整理耗时，也可查看各模型的准备耗时与匹配依据。旧记录保留可用字段。设置中的性能报告统计当前构建最近 100 次准备，另有查询耗时、内存采样和设备状态。报告可单独分享。模拟器测试验证流程，真实图库准确率与速度需用实际手机评估。

README 截图来自隔离的 Android 模拟器。通知卡为虚构示例。相近结果使用获准展示的风景样本，导入演示图库前已去除原始文件名和元数据。仓库保留界面截图。
